# Changelog

All notable changes to Gitr. Each entry is added in the same commit as the change. Newest first.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **Group colours.** With more than one group, each group has a colour, shown as a thin stripe down the left edge of its repositories in the sidebar and on the dashboard, and as a small square next to its name. When All groups is showing and the dashboard is sorted by status, the repositories below **Needs attention** are split by group under each group's name, so you can see at a glance which are Work and which are Personal. New groups get the next unused colour; change it in Settings → Workspace groups.

## [0.1.5] - 2026-10-15

### Changed
- **Push half of the commit button.** The "& Push" half of the commit button is now an upload arrow and **Push**, the same arrow as Push in the toolbar. It still commits first, then pushes (Ctrl+Shift+Enter).

## [0.1.4] - 2026-10-13

### Changed
- **Icon toolbars.** The buttons at the top right are now icons instead of words. In a repository, Fetch, Pull and Push sit together in one small capsule; when there's something to pull or push, the arrow shows the count in blue or green. Open in GitHub/ADO is a globe and Open is a folder, each with a small menu arrow. On the dashboard, Fetch all and Pull all share the same capsule, set apart from Refresh, Rescan and Add folder. Hover over any icon to see what it does and its shortcut.

### Fixed
- **Stop now really stops a hung hook on Windows.** Stopping a commit or push whose hook hangs ended git and the hook's shell, but the commands the hook had started (a lint or test run, say) kept running in the background until they finished by themselves. Stop now ends everything git started.

## [0.1.2] - 2026-10-11

### Added
- **Light/dark toggle in the sidebar.** A sun or moon button next to Settings switches between the light and dark theme in one click. Settings → Appearance → Theme shows the same choice, and still offers Follow Windows.

## [0.1.1] - 2026-10-11

### Changed
- **New look: the ledger.** A cooler, denser window with one violet accent that no longer looks like the blue used for "behind". The dashboard puts repositories that need you in a **Needs attention** band above the rest, its filters (All, Attention, Changes, Behind, Ahead) say how many repositories each would show, and a Behind / Ahead column draws incoming commits to the left of a centre line and outgoing ones to the right. Rows offer Pull, Open in VS Code and the repository menu on hover; Shift+F10 or the menu key opens the menu for the selected row, and Ctrl+F jumps to the search. In a repository, Pull or Push is highlighted when it's the next thing to do, the branch name opens the Branches tab, and the commit button says what it will do ("Commit 3 files to main"). The sidebar's Dashboard item counts the repositories that need attention.
- **The quiet workbench.** One continuous window instead of floating cards on a dotted ground: a soft warm-grey sidebar beside a flat work surface, divided by hairlines. A repository's state is a small mark and a coloured numeral (±, ↓, ↑) instead of a filled chip, the open tab has a thin indigo underline, and the typeface is Hanken Grotesk (bundled).

### Added
- **Update Gitr from inside the app.** A few seconds after it starts, Gitr checks GitHub Releases for a newer version. When there is one, a bar at the top says "Gitr 0.3.0 is available." with **What's new** (the release page), **Restart and update**, and a button that hides it until the next start. Restart and update downloads the new installer, waits for any running commit, pull or checkout to finish, and installs it without questions; Gitr then starts again on the new version. **Settings → Updates** shows the version you have and has **Check for updates**. Updates are signed, and Gitr refuses one whose signature doesn't match. A failed check at startup stays quiet.
- **Add a folder without opening Settings.** The folder button beside the sidebar filter and in the dashboard title bar picks a folder of repositories, adds it as a new group, saves and rescans, then says how many repositories it found. Right-click a group in the sidebar to add a folder to that group. The first-run dashboard and an empty sidebar offer the same button. A folder that is already scanned, or sits inside or around one that is, is refused with a message instead of listing its repositories twice. Unsaved Settings edits keep the new folder.
- **Go to a repository: Ctrl+P.** Type part of a repository's name and press Enter. Names that start with what you type come first; each row shows the repository's dot, group, branch and counts.
- **F6 moves between panes.** F6 and Shift+F6 cycle focus through the sidebar, the file lists, the diff and the commit message (and the lists in History, Branches and Settings), as in Explorer.
- **Dashboard status bar.** Below the table: a tally of every repository ("12 repositories · 4 with changes · 2 behind", or "all clean and up to date") and a legend for the dots and rings.
- **Third-party notices.** The installer puts `THIRD_PARTY_NOTICES.txt` next to Gitr: every Rust crate and npm package that ships in the app, with its licence and the licence texts it carries. `pnpm notices` regenerates it and `pnpm test` fails when it is out of date.
- **History tab.** The repo view has a History tab between Changes and Branches, showing the current branch's commits newest first on a single commit line: the branch and tags at each commit, commits not yet pushed marked with a purple ring and "↑ not pushed", merges with a double ring. Select a commit for its full message, author, parents and changed files with line counts and renames, and a file for its diff (a merge shows what it brought in, against its first parent). Right-click copies the SHA, subject or message, or opens the commit in GitHub or Azure DevOps. It loads 200 commits at a time and reloads only when the branch moves.
- **Revert a commit.** **Revert** in the History tab adds a commit that undoes the selected one, after asking; nothing is pushed. If it conflicts, the repo shows the usual Reverting banner with Continue, Skip and Abort.
- **Reset the branch to a commit, with Undo.** **Reset to here…** moves the branch back to an earlier commit and keeps the changes, staged or unstaged as you choose; files on disk never change and there is no hard reset. The dialog says how many commits leave the branch, warns when some of them were never pushed or are already on the remote (Gitr never force-pushes), and starts on Cancel. **Undo reset** in the toast and above the list puts the branch back until something else changes it.
- **Bisect and `git am` are shown.** A repository in the middle of `git bisect` or `git am` no longer looks normal: the dashboard row gets a "bisecting" or "applying-patches" pill, and the repo view a banner. A bisect's banner has **End bisect** (`git bisect reset`, back to where it started, after asking) and the commit box says to mark commits with `git bisect good` / `git bisect bad` in a terminal; `git am` gets **Continue**, **Skip** and **Abort**. Pull, checkout and Undo last commit wait until it is finished, as for a merge or rebase.
- **Skip during a rebase, cherry-pick, revert or `git am`.** The repo banner has **Skip** next to Continue. It asks first, saying that the commit's changes and any edits made to resolve its conflicts are left out, then goes on with the rest (`git rebase --skip` and so on); a rebase can stop again on the next commit. A merge has no Skip.
- **One sign-in instead of a pile of sign-in windows.** Fetch all and Pull all no longer open Git Credential Manager windows. A repository whose sign-in has expired shows "Sign-in needed", the summary counts them ("Fetched 18/20, 2 need sign-in"), and the dashboard shows a banner with **Sign in**. It signs in once with one of them (one window), then fetches or pulls the others again without asking; repositories on another server get their own single sign-in, and one repository whose sign-in fails doesn't stop the rest. A 403 (no access), a changed SSH host key or a missing repository is reported as a failure with its own message, since signing in can't fix it. Fetch, Pull and Push in the repo view, and Fetch and Pull in a repository's right-click menu, still show the sign-in window when needed.
- **Hooks you can see and skip.** When a commit or push runs your git hooks (pre-commit, commit-msg, pre-push, …), a panel in the repo view shows their output as it is printed, so a slow lint step no longer looks like a hang. If a hook rejects the commit or push, the panel stays with its output and names the hook ("The pre-commit hook rejected the commit."), your commit message stays in the box, and **Commit without hooks** / **Push without hooks** repeats it with `--no-verify` after asking. **Open terminal** and a close button sit next to it.
- **Stop a running operation.** While a repository is busy, its pill on the dashboard and in the repo view has a **Stop** button. It ends the operation and anything queued behind it, including hooks, credential helpers and ssh that git started, so a hung pre-commit hook or a stalled fetch or push no longer needs Task Manager. Fetch and push stop at once; operations that may be writing local files (commit, pull, checkout, rebase, …) ask first. A stopped operation shows "Stopped committing." as information, and the commit message stays in the box. If git was stopped while it held `index.lock`, the message says so and offers **Remove stale lock**.
- **Light and dark themes.** Repositories show as dots whose size shows how many changes they have; clean repositories are hollow and errors and conflicts are red rings, always with a ±, ↓ or ↑ count beside them. File status is a small letter tile, and Lucide icons replace text glyphs. The theme follows Windows, with **System / Light / Dark** in Settings, applied before the first paint; the title bar follows it too.
- **Line counts per changed file.** Each file shows its added and removed lines (+38 −12), split into staged and unstaged (`git diff --numstat`).
- **Mock data for visual testing.** `npm run mock` opens Gitr with synthetic repositories instead of yours (the backend stays idle), and `npm run mock:web` does the same in a browser. A toolbar switches between scenarios (default, many repos, errors, all clean, first run) and theme, and shows sample toasts. See `ui/src/preview/README.md`.
- **Pull handles a diverged branch.** When your branch and the remote have both moved on, Pull in the repo view no longer stops at "Diverged": it asks once, with the facts ("Your branch and origin/main have diverged: 2 local commits, 3 on the remote. Rebase your 2 commits onto origin/main?"), then rebases or merges, stashing uncommitted changes for the operation and putting them back afterwards. It follows `pull.rebase` when the repo's own git config or your global git config sets it (the system-wide `pull.rebase=false` that the Git for Windows installer writes is ignored); otherwise the new **Settings → When branches have diverged** (Rebase by default). A branch that is only behind still fast-forwards without asking.
- **Rebase & push after a rejected push.** The rejected-push toast now offers **Rebase & push** (or **Merge & push**) instead of a Pull that couldn't help, and pushes once the rebase or merge finished cleanly. Its message is now "Your branch and the remote have both moved on. Rebase or merge, then push."
- **Continue a rebase or merge.** When it stops on conflicts Gitr says so ("Stopped on conflicts in 2 files"), and the repo banner has **Continue** next to Abort, enabled once nothing is conflicted. If your uncommitted changes conflict when they are put back, Gitr says so and they stay safe in `git stash list`.
- **Errors offer a fix.** Error toasts now carry a button where there is an obvious next step: **Rebase & push** (or **Merge & push**) when a push is rejected because the remote has new commits; **Remove stale lock** when a leftover `index.lock` blocks git (only while Gitr isn't working on that repo, after a confirmation that names the file); **Trust this folder** when git refuses a folder owned by another user (adds it to `safe.directory` in your global git config, after a confirmation); **Open terminal here** for sign-in, hook and signing failures.
- **Merge, rebase, cherry-pick and revert in progress are shown.** The dashboard row gets a pill ("merging", "rebasing", …) and the repo view a banner with the number of conflicted files and **Abort** (asks first), **Open terminal** and **Open in VS Code**. Pull, checkout, create-and-checkout and Undo last commit are blocked until it is finished or aborted. During a merge, Commit stays available and is prefilled with git's merge message; during the others it is disabled with a hint to continue in a terminal.
- **Gitr finds git, and says when it can't.** It looks in the new **Settings → Git path** (empty = automatic), then PATH, the Git for Windows folders and Scoop, and shows which git it uses and its version. If git is missing or older than 2.27, a banner at the top explains it, with `winget install Git.Git` to copy and **Choose git.exe…** / **Check again**. A new Git path applies immediately.
- **Undo last commit.** The commit box shows **↶ Undo last commit** (with the commit's subject as tooltip) when the last commit has not been pushed and is not a merge commit. Undoing asks no question: the branch moves back one commit, all of its changes stay staged, and its full message returns to the commit box. It also works for a repository's first commit.
- **Discard asks before deleting anything permanently.** The confirmation now says the current version goes to the Recycle Bin. If some files can't be moved there, Gitr asks "Couldn't move N file(s) to the Recycle Bin: … Discard them permanently?"; No leaves them untouched.
- **Busy repositories show what they are doing.** A repository running a change shows the operation (e.g. "committing…", "pulling…") as a pill on its dashboard row, a pulsing dot in the sidebar and a label in the repo view toolbar. In the repo view, every action that would change the repository (fetch/pull/push, commit, stage/unstage/discard including keyboard shortcuts and double-click, and branch checkout/create/delete) is disabled until it is done. Busy state appears only after 200 ms so quick actions such as staging one file don't make buttons flicker; actions in that window are queued safely.
- **Log files.** Daily files in `%APPDATA%\gitr\logs` (14 kept). Each git call writes one line, with credentials in URLs replaced by `***`. Panics are logged, `GITR_LOG` sets the level (default `info`), and Settings has an **Open logs folder** button.

### Changed
- **Conflicts look like conflicts.** A conflicted file has git's own **U** on a solid red tile (it was a purple C, the same as a copied file), heads the Unstaged list and opens on its own. Above its diff a note says what to do, with **Open in VS Code** and **Mark resolved** (stages it). The operation banner and the dashboard pill are red while conflicts remain and neutral otherwise, no longer the orange of uncommitted changes; the pill counts them ("merging · 2 conflicts"). Untracked files show **?** instead of U.
- **The sidebar is one Tab stop.** Arrow keys move through groups and repositories, Left and Right fold and unfold a group, Home and End jump. Tab no longer visits every repository.
- **The sidebar becomes a strip in narrow windows.** Below 1100px wide it shows only the state dots (names in tooltips and for screen readers), and the file list narrows before the diff does, so the diff keeps its room.
- **First run explains itself.** With no groups yet, Settings says what a group is and offers **Choose a folder…** as the main button; the first folder is saved at once, so the sidebar fills in without pressing Save. The empty sidebar says where repositories come from.
- **Dashboard rows read like the sidebar.** Behind, ahead and changes use the same ↓ ↑ ± chips, with a dash when there is nothing. Fetch all / Pull all results are plain words ("Up to date", "Pull failed · …"), a row that needs a sign-in says so quietly under the banner, and rows keep their places while the results are shown.
- **Screen readers hear file status.** Status tiles are read as "Modified", "Conflicted", "Untracked" …, and the selected file is announced as the arrow keys move through the Changes lists.
- **Development uses pnpm and Vite+.** `pnpm install`, `pnpm dev`, `pnpm test` and `pnpm build` replace the npm commands; the UI runs on Vite+ (`vp dev`, `vp build`, `vp test`, `vp lint`, `vp fmt`), configured in `ui/vite.config.ts`, and Oxfmt formats the code in its existing style (single quotes, no semicolons, 140 columns). The dev container adds the Oxc VS Code extension as the formatter.
- **Dashboard rows don't walk untracked folders.** The dashboard and sidebar now count an untracked folder as one change (`git status --untracked-files=normal`), so a large unignored build or `node_modules` folder no longer slows every refresh. The repo view's Changes list still lists every file, and its tab count now matches that list.
- **SSH never waits for an answer.** Unless you set up SSH yourself (`GIT_SSH_COMMAND`, `GIT_SSH` or `core.sshCommand`), Gitr runs ssh so that a server's key is accepted the first time (a changed key is still refused), it never asks for a typed password, and in Fetch all / Pull all it asks nothing at all: a key that needs a passphrase fails with "Sign-in needed" instead of hanging.
- **Gitr rests while you work elsewhere.** While its window is in the background, file changes no longer trigger `git status` runs; Gitr notes which repositories changed and refreshes each of them once when you switch back. Refreshes after Gitr's own fetches, pulls and commits still run in the background. Switching back also refreshes the open repository, so changes the file watcher missed show up.
- **Hook failures are recognised exactly.** Gitr reads which hook failed from git's own trace instead of guessing from whether a hook file exists. A commit that fails for another reason in a repo with hooks is no longer called a hook failure, and a hook whose output mentions a network or lock error is no longer mistaken for one.
- **Gitr now needs Git 2.27 or newer** (was 2.25), for `merge --autostash`. The git banner says so for older versions.
- **Clearer error messages.** Git failures are recognised by kind (push rejected, lock file, local changes overwritten, folder owned by another user, sign-in, network, signing, hook, not a repository, conflicts) and shown in plain language, for example "Your branch and the remote have both moved on. Rebase or merge, then push." git's own output is still under **details**, now including what git printed to stdout (a rejected push's reason was missing before). A failing hook is recognised even though it prints only its own output.
- **Pull all explains diverged repositories better:** "Diverged from upstream. Open the repo to rebase or merge." Pull all itself still only fast-forwards.
- **Discard moves files to the Recycle Bin.** Before reverting a modified file or removing an untracked one, Gitr moves the current version to the Windows Recycle Bin, where it keeps its name and original location, so "Restore" puts it back. Staged changes are still kept. Files on drives without a Recycle Bin (network, removable) and files the bin refuses are left untouched instead of being deleted.
- **Untracked files are deleted by Gitr itself instead of `git clean`.** Only files git lists as untracked (not ignored) are deleted, and every path is checked before anything is removed.
- **Tests run against an isolated git environment**: no global or system config, fixed identities and dates. New regression tests cover risky file names, long path lists, slow hooks, editors and log redaction.

### Fixed
- **A merge or rebase waiting no longer looks like an ordinary repository.** On the dashboard and in the sidebar it has its own mark, it sorts with the repositories that have conflicts, and the Attention filter (formerly Errors) now also shows conflicts, operations in progress and failed Fetch all / Pull all results.
- **Split diff** gave the old side almost all the width and cut the new side off at the window edge, with the divider in a different place in each hunk. Each side now gets half, and long lines wrap inside their half.
- **Commit button off screen** in a short window during a rebase or cherry-pick: the commit box now always stays in its panel, and the file lists shrink first.
- **The shortcut list in Settings** said Ctrl+Tab switches between Changes and Branches; it steps through Changes, History and Branches.
- **The "Select a file to view its diff" hint** failed AA contrast in the light theme.
- **Files whose names aren't valid UTF-8 can be staged, diffed and discarded.** A Latin-1 name such as `caf\xe9.txt` (possible on Linux and macOS) was shown with `�` and git rejected the path when you acted on it. The name is now kept as git printed it. In the list the odd byte may show as a placeholder glyph.
- The Changes tab counted a conflicted file twice. It now shows the number of entries in the Changes list.
- The commit box told you to continue a rebase, cherry-pick or revert in a terminal, although the banner has had **Continue** since diverged-pull. It now points to the banner first.
- **Rows no longer go stale after a burst of file changes.** When the operating system dropped file-change events (for example during a large checkout), Gitr ignored the error and some repositories kept showing old state. Now every repository is refreshed.
- **An idle repository no longer refreshes in a loop.** With `core.fsmonitor` enabled, every `git status` writes a cookie file inside `.git`, which the file watcher took for a change, so it started the next `git status`: about 300 runs in 75 seconds on an idle repo. The watcher now only reacts to the parts of `.git` that change what Gitr shows (HEAD, index, refs, packed-refs, config, fetch/merge/rebase/cherry-pick state) and ignores git's own bookkeeping.
- **Changes to `Cargo.lock`, `yarn.lock` and other worktree files ending in `.lock` now refresh the repository.** The watcher used to ignore every `*.lock` file, not just git's internal lock files.
- **A repository inside two groups is no longer listed twice.** When a repo is reachable from several group roots (for example a group for the repo itself and one for its parent folder), it now appears once, in the group whose root is closest to it. Before, `rescan` only removed duplicates that happened to be next to each other.
- **Actions on the same repository no longer run on top of each other.** Stage, unstage, discard, commit, checkout, branch create/delete, pull and push now wait their turn per repository, in the order they were requested. Before, overlapping actions could fail with `index.lock` errors or interleave (for example a pull during a commit). Status and diffs never wait.
- **Fetch all / Pull all skip a repository that is busy** with another change and show "skipped · busy (committing)" for it. The rest of the batch carries on.
- **A fetch or pull already running on a repository is joined, not repeated.** For example, clicking Fetch in the repo view during Fetch all waits for that fetch and reports its result, and git runs once.
- **File-change refreshes are merged per repository** (one running, one queued) and held back while a change is running, so a burst of file events no longer starts many `git status` runs.
- **Discard, stage and unstage no longer treat file names as patterns.** Discarding `a[12].txt` used to also delete `a1.txt` and `a2.txt`. Every git command now runs with literal pathspecs (`GIT_LITERAL_PATHSPECS=1`), and file lists are passed through stdin in one call, which also removes the Windows command-line length limit.
- **Commits, merges, checkouts and other local writes are no longer killed after 30 s.** Before, a slow pre-commit hook or an LFS download during a pull could be cut off mid-write and leave `.git/index.lock` behind. Reads still time out after 30 s and fetch/push after 300 s.
- **Git can never block on an editor.** `GIT_EDITOR=true` and `GIT_MERGE_AUTOEDIT=no` are set on every command.
